## 앱에 새로 생긴 것 (v6.3)
- **여정 맨 위 띠 2개** : 초록 = 제가 반영한 것(inbox) / 청록 = **「제가 채운 것 n건」** → 누르면 목록, 각각 「맞아(확정)」 「아니야🎙」 「열쇠 열기」
- 제가 넣은 열쇠는 전부 `from` 필드가 있고 **확정이 아니다**. 프로님이 「맞아」 를 눌러야 확정. `claudeFilled()` 가 그 필드로 골라낸다
- **설정 › 연동 상태** : 원천 6개의 마지막 갱신일·건수 (`meta/feedsrc`)
- **설정 › 제가 반영한 것** : inbox 전체 이력
- 담당자 줄에 통화 건수·최종 통화일

## 새 창이 할 일 (연동을 계속 돌리는 법)
1. `ArtifactData list meta` → `outbox` 에 프로님이 보낸 줄이 있으면 먼저 처리하고, 처리 결과를 `meta/inbox` 에 한 줄 추가한다(프로님이 앱에서 본다).
2. `ArtifactData list sites` → `req` 중 `state:'확정'` 이고 `basis` 에 「프로님 확인/고치심」 이 있는 것 = **프로님 결정**. 확정 대장에 반영하고 절대 덮지 않는다.
3. 새 대장·회의록이 생겼으면 `feed.py` 를 고쳐 돌리고 batch 로 쓴다. **기존 문서는 list 로 버전을 먼저 읽어 `if_version` 을 붙인다.**
4. 쓴 뒤 `meta/feedsrc` 의 날짜·건수를 갱신하고 `meta/inbox` 에 「무엇을 넣었는지」 한 줄.

## v6.4 추가 (같은 날 저녁) — 「좀더 볼래?」 에 대한 점검 결과
프로님 : *"만들어도 이젠 되겠어? 좀더 볼래?"* → 데이터 품질을 다시 보고 3가지를 고쳤다.

1. **담당자 이름이 잘못 잘렸다** — 「능홍○○ 부장」(일능+홍○○), 「팀박○○ 과장」, 「크주○○ 대표」. 회사 접두어(일능·참빛파워텍·국보·루테크·LFE&C·태석계전·서영서·유성씨앤씨·정상티이씨·신세계건설·삼우MEP…)와 현장명을 먼저 떼고 직함 앞 2~3자를 이름으로. 4자로 잡히면 뒤 3자. 직함이 없으면 **자르지 않고 원문 그대로**(짐작으로 이름을 만들지 않는다). 직함에 대리·파트장·실장·본부장·주임 추가.
2. **통화 15건인 김○○ 팀장(도어락)이 미배정이었다** — 확정 대장의 「근거」 문구("260917 김○○ 팀장 14:56 통화")에서 이름을 뽑아 그 현장으로 붙인다. 근거에 이름이 없으면 그대로 미배정.
3. **미배정 51명이 앱에서 죽은 데이터였다** — 「현장」 탭 맨 위에 「현장을 못 정한 연락처 n명」 띠. 누르면 목록, 드롭다운으로 현장을 고르면 그 현장 사람 탭으로 들어가고 `담당자,…` 줄이 보내기에 담긴다. 「+ 새 현장」 「안 씀」 도 있다.
4. **현장 이름 고치기 허용** — 제가 통화 기록에서 뽑은 이름(염곡동·해운대·청담PJ·고급주택·워케이션·지경리)은 지역·용도일 수 있다. 「정보 고치기」 에서 이름을 바꾸면 그 현장의 줄·회의가 따라 바뀌고 `현장명,옛→새,프로님이 고치심` 이 보내기에 담긴다. **id 는 그대로**라 이력이 끊기지 않는다.

시험 : 8개 중 6개 통과(실패 2건은 시험 코드가 앞 화면에 머문 문제, 앱 오류 아님). 페이지 오류 0.

## v6.5 「회의록 기준」 (2026-09-19 밤) — 프로님 지적 3가지를 받아
프로님 : *"공정에 대한 내용이 업그레이드 덜 됐고 할 일 반영 덜 됐어. **회의록 기준이 중요해.** 비서 같은 앱이 필요한 거야."*

### 무엇이 덜 됐었나
대장(확정사항·통화기록)만 읽고 **회의록 분석 결과를 안 읽었다.** 레포에 이미 있던 것 :
- `산출물/260918_녹취에서_뽑은_것.html` — **현장 32곳** · 통화 81명 · 회의 48건 화제 · **후속 끊긴 분 14명** · 현장별 「안 한 지 n일」
- `산출물/260918_못읽은녹취_9건_판독.html` — KM-001~003 의 근거와 보낼 메일 문안
그래서 앱에 현장이 11곳뿐이었고, 할 일 16건이 어느 공정 단계의 것인지 안 붙어 있었다.

### 고친 것 (`앱/연동2_회의록기준_feed2.py`)
1. **현장 31곳** — 32곳 표에서 읽음. 각 현장에 `calls`(통화 건수) · `lastCall`(마지막 통화) · `idleDays`(안 한 지) · `mainWho`(주로 통화한 분).
2. **할 일 ↔ 공정 단계 연결** — 16건 전부 `quest` 필드를 붙였다(타공도→외함설치 / 도어락·승인원→기구물제작 / 수량·계량기·견적→계약 / 도면→설계 …). 단계를 열면 「이 단계의 할 일 n · 회의록에서 나온 것」 으로 카드가 뜨고, 거기서 바로 문안·완료·아니야.
3. **조용한 현장** — 마지막 통화에서 오늘까지 센다. 7일↑ 주황, 14일↑ 빨강. 여정 카드에 「23일째 조용」.
4. **연락 끊긴 곳** — 오늘 화면에 절 신설. 조용한 현장 + 후속 끊긴 분 12명(`meta/drops`). 예) 전남연수원 23일째 · 청담PJ 22일째 · 조선호텔 진○○ 대리 26일.
5. **여정 정렬 4가지** — 급한순(기본, 할 일 수 + 조용한 날) / 조용한순 / 진행순 / 이름순.

### 새 창이 이어서 할 것
- `feed2.py` 가 정본. 새 녹취 분석 HTML 이 나오면 경로만 바꿔 다시 돌린다.
- 할 일을 새로 넣을 때 **반드시 `quest` 를 붙인다**(QMAP 정규식 참고). 안 붙이면 단계에 안 보이고 글자 매칭으로 떨어진다.
- 현장 31곳 중 상당수가 지역·용도 이름(염곡동·해운대·청담PJ·고급주택·워케이션·지경리·단양디캠프). 프로님이 「정보 고치기」 로 바꾸시면 그 이름이 정본.
- 공정(열쇠)은 아직 연합기숙사 6 · 양양쏠비치 3 뿐. **나머지 29곳은 회의록 본문을 읽어야 채워진다** — PLAUD 직접 읽기는 비싸므로(규칙 33) 프로님 요청 시 또는 주 1회.

## v6.6 「계약 게이트 + PC 피드」 (2026-09-19 밤)
프로님 : *"코드는 회의록을 읽는데 비용이 0이지? 각 앱 내용이 회의록에 생기면 즉시 앱에 반영해야 돼. **물건 만들기 전 계산서 및 계약 요청해.**"*

### 1. 계약·계산서 게이트 (업무 규칙을 앱이 지킨다)
- 외함 · 속판 · 기구물 **세 제작 단계마다** 의뢰서 열쇠 **앞에** 「★ 계약 · 계산서 확인 (제작 전)」 열쇠를 넣었다(`gate:true`). 열쇠가 38 → **41개**.
- 그 게이트가 확정이 아니면 **작업의뢰서 열쇠를 열었을 때 빨간 자물쇠**가 뜬다 : 「계약·계산서가 먼저입니다」 + 「계약·계산서 열쇠 열기」 「계약·계산서 요청 문안」.
- 문안(`moneyDraft`)은 계약 현재 상태·계약 형태를 그대로 넣고, 계산서 구분(선금/기성/납품)·금액 `[ ]`·발행 요청일·사업자 정보 칸과 **제작 기간(외함 2주 / 속판 2달 / 기구물 1.5~2달)이 늦어지면 현장 일정에 영향**이라는 근거를 붙인다. 금액은 앱이 정하지 않는다.
- 막기만 하지 않는다 — 프로님이 확정을 누르시면 그대로 통과한다(경고이지 잠금이 아니다).

### 2. 회의록은 PC 파이썬이 읽는다 (토큰 0) — `앱/PC도구/t49_appfeed.py`
- 읽는 것 : `plaud\**\원문.txt`(_현장비서 v10 결과) · 확정사항 · 앞으로할것 · 현장대장.
- 뽑는 것 : 현장 · 마지막 회의일 · **열쇠**(KEYMAP 정규식으로 「외함 납품 10/15」 → `외함/외함납기` 추정) · **할 일 + 공정단계**(QMAP) · 확정값.
- 내는 것 : `_도구결과\앱피드\{YYMMDD}\앱피드.json` + **클립보드 복사** + 앱 열기.
- 시험 : 조선호텔 가짜 회의록 1건 → 열쇠 2 · 할 일 3(회의록·대장 중복은 `T-`+해시로 합침) · 마지막 회의 2026-09-18 확인.
- **QMAP·KEYMAP 은 앱 코드와 같은 규칙이다. 한쪽을 고치면 반드시 양쪽 다 고칠 것.**

### 3. 앱이 그것을 받는다 — 설정 › 「PC에서 붙여넣기」
- `takeFeed()` : 현장·할 일·열쇠를 병합한다. **프로님이 확정한 열쇠는 덮지 않고**, 끝난 할 일은 되살리지 않으며, 같은 것을 두 번 넣어도 늘지 않는다(시험 통과).
- 받은 뒤 `meta/inbox` 에 「PC 49번에서 받음 — 현장 n · 할 일 n · 열쇠 n」 이 남아 여정 맨 위에 뜬다.
- **왜 붙여넣기가 남나** : 아티팩트 페이지는 보안 규칙상 외부 주소(GitHub 등)를 직접 읽지 못한다. 그래서 PC → 클립보드 → 앱 붙여넣기가 지금 가능한 가장 짧은 길이다(손 2번). 더 줄이려면 ① 제가 창을 열 때 레포에서 읽어 db 에 쓰거나 ② 프로님이 「앱 갱신해」 한마디를 하시는 길이 있다.

## v6.7 「결정과 질문 창고」 (2026-09-19 밤)
프로님 : *"꼼꼼히 봐야 해. 반영도 빠르고, 이 앱이 비서이면서 **서로 결정과 질문 해결 창고**가 되면 좋겠어."*

### 새 탭 「창고」 — 세 칸
1. **제가 여쭙는 것** (`asks` 컬렉션, `who:'클로드'`) — 인수인계함의 결정대기를 앱으로 옮겼다. **15건 넣음**(현장대장·수금대장·설계예산 배수·단가장 v70 중복·앵커 배선도·견적서 원틀·설치 사진 위치·원틀 3종·건축HUB 키·아침메일 vs 앱·저장소 공개 처리·시운전 확인 방법·계산서 시점·현장 이름 정리·미배정 50명).
   - 선택지 단추 / 말로 답하기🎙 / 모르겠음·나중에.
   - **3일 넘게 답이 없으면 빨간 테두리**(규칙 35 묵은 제안). 「나중에」 는 날짜를 새로 찍어 다시 올라온다.
   - `reqKey` 를 붙여 두면 답이 곧바로 그 현장 **열쇠 확정**으로 들어간다.
2. **프로님이 물으신 것** (`who:'프로님'`) — 맨 아래 「＋ 클로드에게 물어보기 🎙」. 말로 물으시면 `질문,현장,내용` 이 보내기에 담기고, 새 창의 제가 답하면 창고에 남는다.
3. **정해진 것** — 문답 답 + 현장 확정값(facts) + 확정된 열쇠를 **한 목록**으로 모아 날짜순. 찾기칸은 폰 안에서 돌아 **비용 0**. 연합기숙사로 찾으니 7건이 나왔다.

## 양방향 4고리 — 지금 상태
| 고리 | 어떻게 | 상태 |
|---|---|---|
| 데이터 → 클로드 | 레포의 PC 도구 결과를 git show 로 읽음 | **됨** (토큰 적게) |
| 클로드 → 앱 | `ArtifactData` batch 로 `sites`/`meta` 에 씀. **if_version 필수** (기존 문서는 먼저 list 로 읽고 버전 확인) | **됨** |
| 앱 → 클로드 | `meta/outbox` 의 한 줄들, `sites/*.req` 의 프로님 확정 | **됨** (읽기만 하면 됨) |
| 클로드 → 프로님 알림 | `meta/inbox` = `{lines:[{ts,text,seen}]}` → 앱 맨 위 초록 띠 「제가 반영했습니다」 | **됨** |

## 앱에 새로 생긴 것 (v6.3)
- **여정 맨 위 띠 2개** : 초록 = 제가 반영한 것(inbox) / 청록 = **「제가 채운 것 n건」** → 누르면 목록, 각각 「맞아(확정)」 「아니야🎙」 「열쇠 열기」
- 제가 넣은 열쇠는 전부 `from` 필드가 있고 **확정이 아니다**. 프로님이 「맞아」 를 눌러야 확정. `claudeFilled()` 가 그 필드로 골라낸다
- **설정 › 연동 상태** : 원천 6개의 마지막 갱신일·건수 (`meta/feedsrc`)
- **설정 › 제가 반영한 것** : inbox 전체 이력
- 담당자 줄에 통화 건수·최종 통화일

## 새 창이 할 일 (연동을 계속 돌리는 법)
1. `ArtifactData list meta` → `outbox` 에 프로님이 보낸 줄이 있으면 먼저 처리하고, 처리 결과를 `meta/inbox` 에 한 줄 추가한다(프로님이 앱에서 본다).
2. `ArtifactData list sites` → `req` 중 `state:'확정'` 이고 `basis` 에 「프로님 확인/고치심」 이 있는 것 = **프로님 결정**. 확정 대장에 반영하고 절대 덮지 않는다.
3. 새 대장·회의록이 생겼으면 `feed.py` 를 고쳐 돌리고 batch 로 쓴다. **기존 문서는 list 로 버전을 먼저 읽어 `if_version` 을 붙인다.**
4. 쓴 뒤 `meta/feedsrc` 의 날짜·건수를 갱신하고 `meta/inbox` 에 「무엇을 넣었는지」 한 줄.

## 규칙 (깨지 말 것)
- 제가 넣는 값은 **추정·진행중**. 확정은 프로님 단추만.
- 현장 판정은 이름에 현장명이 있을 때만. 없으면 `meta/contacts` 에 두고 프로님께 여쭙는다(짐작으로 옮기지 않는다).
- 프로님이 「아니야」 로 고친 값은 `prev` 에 이전 값을 남기고 확정된다. 새 연동이 그것을 덮지 않는다(`setReq` 가 확정을 보호).

## 스마트 호텔 4단계 (이것이 이 제안서의 축)
- **Level 1 기본 제어** — 키센서 3모드. 표준 제공. 발주처 준비 없음
- **Level 2 통합 운영** — PMS 연동 + 방재실 감시. 발주처는 PMS 서버·전용망
- **Level 3 모바일·연동** — MMO 모바일, 도어락·에어컨·바닥난방·커튼. 발주처는 공인 IP·Wi-Fi AP
- **Level 4 콘텐츠·센서** — 나이트테이블 콘텐츠, 누수·움직임 감지, 데이터 1년

전부 **회사가 이미 하고 있는 것**이다. 지어낸 기능은 없다. 근거는 회사소개 pptx · MMO 제안서 요약 · 운영매뉴얼 상수.

바뀐 것은 **빌더**뿐이다. 새 창은 이 사실을 먼저 알 것 — r6에서 문구·수치를 찾지 말 것.

## 무엇이 오류였나
python-pptx로 38장을 전수 검사해 **가로 넘침·겹침 9건**을 찾았다 (6·8·13·14·16·23·24·32·34장).
원인은 전부 같다 — 주석(note)·캡션(caption)·헤드라인 높이가 **고정값**이라, 한글이 2줄이 되면 아래 요소를 덮었다.
한 장씩 문구를 줄이는 방식은 다음 판에서 또 터진다. 그래서 **빌더를 고쳤다**.

## 빌더 v2 — `빌더/build_proposal_v2.js` ★ 다음 창은 반드시 이것을 쓸 것
km-proposal 스킬의 `build_proposal.js`를 복사해 고친 것이다. 스킬 원본에는 아직 반영하지 않았다.

```js
// 한글은 폭 1.0em, 라틴은 0.52em으로 잡아 줄 수를 추정한다
function estLines(text, widthIn, fontPt)   // → 줄 수
function textH(text, widthIn, fontPt, pad) // → 필요한 높이(in)
```
- 모든 note·caption·headline·banner·deadline 높이를 `textH()`로 계산 → **고정값을 전부 없앴다**
- table 장은 `avail = M.BOT - y - noteH`로 표 높이를 역산 (주석이 길면 표가 알아서 줄어든다)
- conclusion 카드는 본문 상단 정렬 + 카드 높이 자동
- 검사 결과 **9건 → 0건**

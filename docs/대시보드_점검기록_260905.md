## v5.8에서 고친 오류 (2026-09-05, 검증: 헤드리스 Chromium에 고장 데이터 주입해 구판=크래시 / 신판=정상 확인)
| # | 증상 | 원인 | 조치 |
|---|---|---|---|
| 1 | 09:00 KST 이전에 「오늘 업무일지 미작성」 경보·D-day가 어제 기준 | `td()`가 UTC 날짜(toISOString) | 로컬 날짜로 교체, 날짜 비교는 `ld()` 로컬 파싱 |
| 2 | 배열이 빠진 현장 데이터(옛 판·서버) 로드 시 화면 전체 백지 | `s.issues.filter` 등 미가드 | `normSites()`로 로드 직후 형태 보정 |
| 3 | 수정 후 30초 안에 닫으면 유실, 저장 실패는 조용히 무시 | 43개 수정 함수가 저장 안 함, `catch(e){}` | 화면 갱신마다 0.4초 디바운스 저장 + 닫기 직전 저장 + 실패 시 빨간 상태·토스트 |
| 4 | 메모·계산·의뢰서·문서·패널 항목 삭제가 확인 없음 | confirm 누락 6곳 | confirm 추가 |
| 5 | 현장명에 `'`, 메모에 `<` 있으면 클릭 깨짐·HTML 주입 | innerHTML 미이스케이프 | `esc()` 도입, 핫스팟 5곳 적용 |
| 6 | 서버 데이터가 더 오래돼도 로컬 수정분을 덮어씀 | 시각 비교 없음 | `_ts` 비교, 로컬이 최신이면 덮지 않고 알림 |
| 7 | 홈 화면 추가 시 작업거점 파인더가 열림 | manifest가 cafe-finder 전용 | `manifest-pm.json` 신설 + index.html 링크 |

## 독립 감사(다른 에이전트, 읽기 전용) 결과와 재수정 — 2026-09-05
감사자가 위 7건 중 3건에서 놓친 곳을 찾았고 전부 재수정했다(검증: 헤드리스 Chromium에 `O'Brien 호텔 <테스트>` 현장·손상 JSON 주입).
| # | 감사 지적 | 조치 |
|---|---|---|
| 1 | 미결이슈 탭(renderIssues)에 UTC 날짜 비교 1곳 잔존 | `ld()`로 교체, 잔존 0건 확인 |
| 2 | 이번 주 예정 계산의 주 경계가 자정이 아님 | 시작점을 `ld(td())` 자정으로 |
| 3 | 현장명에 `'`가 있으면 업무일지 현장 삽입 onclick이 여전히 깨짐(HTML 파서가 `&#39;`를 먼저 풀어버림) | 이름 대신 현장 id를 넘기고 함수 안에서 이름 조회 |
| 4 | 손상된 localStorage JSON이 빈 데이터로 덮여 복구 불가 | 파싱 실패 시 `_corrupt_시각` 키로 원문 백업 후 진행 |
| 5 | 서버 데이터에 `_ts`가 없으면(구판 클라이언트가 저장) 로컬이 최신이어도 조용히 덮어씀 | 시각 불명이면 confirm으로 교체 여부를 묻고 기본은 로컬 유지 |
| 6 | 저장 실패 문구가 원인 불문 「용량 초과」 | QuotaExceeded만 용량 초과, 그 외는 오류명 표시 |
감사자가 확인 못 한 것: Apps Script 서버가 `_ts`를 실제로 저장·반환하는지(서버 코드 열람 불가).

코인 자동매매 브리지 v2.4 · 2026-09-13 · 실제로 쏘기 전에 5분만 읽으면 됩니다
한 줄 결론: 이유를 보는 곳은 딱 3군데입니다 — ①트레이딩뷰 알림 패널의 Log 탭 ②구글 시트 「1.거래로그」 ③딥코인 앱. 위에서부터 순서대로 보면 어디서 막혔는지 30초면 나옵니다. 다만 지금 한 군데가 비어 있습니다(아래 6번).
⚠ 먼저 알아야 할 함정 — 빨강 X 를 보고 다시 쏘지 마십시오
트레이딩뷰는 3초 안에 응답이 안 오면 요청을 취소하고 빨강 X로 표시합니다. 그런데 구글 앱스스크립트는 취소된 뒤에도 계속 돌아서 주문을 냅니다. 즉 트레이딩뷰는 실패라고 하는데 딥코인엔 주문이 들어간 상황이 실제로 생길 수 있습니다.
판정 규칙: 트레이딩뷰가 빨강 X 라도 → 시트 「1.거래로그」에 그 시각 행이 있으면 주문은 나간 것입니다. 손으로 다시 넣지 마십시오.
(트레이딩뷰는 타임아웃·연결거부에는 재시도하지 않습니다. HTTP 500번대일 때만 5초 간격 3회 재시도하는데, 그건 우리 브리지의 중복 차단이 막습니다.)

2

알럿이 울렸는가

알럿이 만료됐거나(플랜별 약 2개월), 플랜 알럿 개수를 넘겼거나, 조건이 「봉 마감 시」인데 봉이 안 닫혔으면 안 울립니다.

트레이딩뷰 오른쪽 알림 패널 → Log 탭 (알럿이 목록에 뜨는가)

같은 Log 탭에 초록 체크면 우리 서버가 정상 응답, 빨강 X면 주소 오타·3초 초과·연결 거부입니다. 항목을 누르면 보낸 메시지 원문과 응답이 보입니다.

5

거래소가 주문을 받았는가

딥코인이 거절하면 ERROR + 사유 코드(sCode=36 잔고부족 등). 나갔으면 LIVE + 주문번호 + 검증 결과(OK / ⚠ / PARTIAL).

시트 「1.거래로그」 + 딥코인 앱 주문내역 · 메일(또는 텔레그램)
▼
6

둘 다 아무 흔적이 없다 ← 지금 여기가 비어 있습니다

트레이딩뷰는 보냈다는데 시트에 행이 없는 경우입니다. 스크립트 권한 만료, 구글 일일 한도 초과, 배포 URL 변경 같은 사고인데 지금은 알 방법이 없습니다. 조용히 며칠 안 돌아도 모릅니다.

지금은 볼 데가 없음 → 아래 계획 B-2 워치독으로 메움

증상별 — 어디부터 보나 (3줄 판정)

증상먼저 볼 곳판정
아무 일도 안 일어났다트레이딩뷰 Log 탭목록에 알럿이 없으면 1~2번(전략·알럿) 문제, 있으면 4번으로
Log에 빨강 X시트 「1.거래로그」 같은 시각행이 있으면 주문 나감(다시 쏘지 말 것) · 없으면 주소·배포 문제
시트에 REJECT상세 열의 한글 사유사유가 곧 답. 주문은 안 나갔으니 급하지 않음
시트에 ERROR오류 열의 sCode거래소가 거절. 잔고·수량·손절값 확인
검증에 ⚠ PARTIAL딥코인 앱 포지션일부만 체결. 앱에서 직접 정리
며칠째 조용하다시트 「0.자가진단」의 마지막 웹훅날짜가 오래됐으면 6번 사고 — 지금은 자동 경고가 없음

계획 — 무엇을 언제 하나

A · 오늘 · 코드 안 건드림보는 법 익히기

  • 트레이딩뷰 오른쪽 알림 패널 → Log 탭 위치를 한 번 열어 확인 (여기가 1·2·3번 증거)
  • 시트 「1.거래로그」를 폰 즐겨찾기에 (여기가 4·5번 증거)
  • 위 빨강 X 함정 규칙 하나만 외우기 — 빨강 X + 시트에 행 있음 = 주문 나감

B · 차장님이 확인만트레이딩뷰 쪽 3가지

  • 플랜: 웹훅은 Essential 이상에서만 됩니다. 무료 플랜이면 URL 칸이 아예 회색입니다
  • 알럿 만료: 만들 때 만료를 「무기한」으로 (플랜이 지원할 때). 아니면 약 2달 뒤 조용히 멈춥니다
  • 알럿 개수: 플랜 상한을 넘기면 새 알럿이 조용히 비활성화됩니다

C · 승인하시면 제가 코드로v2.5 — 구멍 3개 메우기

  • C-1 접수 먼저 기록: 지금은 처리가 다 끝나야 시트에 한 줄 씁니다. 받자마자 「접수」 줄을 먼저 쓰고 끝나면 결과로 갱신 → 6번 구멍이 절반 메워집니다
  • C-2 무소식 워치독: 마지막 웹훅이 정해둔 시간(예: 24시간)을 넘기면 아침 자가진단이 FAIL + 알림. 조용한 고장을 잡는 유일한 장치
  • C-3 처리시간 기록: 요청마다 걸린 밀리초를 로그 열에 추가 → 3초를 넘는지 추측이 아니라 숫자로 보입니다

3초 문제 — 대안 3개와 각각 잃는 것

안얻는 것잃는 것
가 (권장)그대로 두고 빨강 X를 무시하는 규칙으로 운영코드 안 건드림. 트레이딩뷰는 타임아웃에 재시도하지 않으므로 이중 주문 위험 없음Log 탭이 빨강으로 지저분해짐. 진짜 실패와 눈으로 구분해야 함 → 그래서 C-3 처리시간 기록이 같이 필요
나주문 전 포지션 조회를 빼서 빠르게 만듦3초 안에 들어올 가능성이 높아짐안전장치를 빼는 것 — 중복 진입·잘못된 청산 수량을 막던 문이 사라짐. 권하지 않음
다알럿은 받아 적기만 하고, 1분 트리거가 주문트레이딩뷰엔 항상 초록 체크주문이 최대 1분 늦음. 시장가 매매에서 1분은 치명적

지금 확실한 것 / 아직 모르는 것

확실근거
트레이딩뷰 응답 제한 3초, 타임아웃엔 재시도 없음트레이딩뷰 공식 안내(웹훅 오류 문서) 인용 검색 결과
HTTP 500번대만 5초 간격 3회 재시도같은 문서 — 우리 브리지는 중복 id 로 막음
익명 웹앱 요청은 앱스스크립트 실행기록에 로그가 안 남을 수 있음그래서 시트 로그가 정본이라는 설계가 맞음
아직 모름어떻게 확인하나
우리 브리지가 실제로 몇 초 걸리는지추정 3~8초 — 실측 안 함. C-3 처리시간 기록을 넣어야 숫자가 나옴
트레이딩뷰가 구글의 302 넘김을 잘 따라가는지실제로 한 번 쏴 보면 Log 탭에 바로 나옴 (첫 알럿이 곧 시험)
딥코인이 손절을 주문에 붙여 유지하는지소액 1계약 넣고 앱에서 눈으로
※ 이 문서는 설계·계획 문서입니다. 지어낸 값 없음 — 표의 상태·사유 문구는 코드에 실제로 들어 있는 문자열이고, 3초·재시도 규칙은 검색으로 확인한 트레이딩뷰 규정입니다. 「추정 3~8초」만 계산에 의한 추정이며 실측이 아닙니다. 상한·기간 숫자는 차장님이 정하는 값입니다.

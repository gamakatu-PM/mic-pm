# 백테스트 — 2단계 (2026-09-20)

> 1단계(브리지로 주문 내기)는 설치 벽에 막혔고, 돈은 이미 굴러가고 있는데 수익이 없다.
> 그래서 2단계는 **돈 한 푼 안 걸고 「왜 안 되는지」를 숫자로 보는 것**이다. 결과는 `report.html`.

## 결론 한 줄
수수료가 범인이다. 같은 전략·같은 파라미터로 **수수료만** 바꾸니 편도 0.40%에서 이익의 **91%가 사라졌다**.

## 실행
```
node coin/backtest/selftest.js     # 엔진 자가시험 19건 (먼저 이게 통과해야 나머지를 믿는다)
node coin/backtest/run.js          # 워크포워드 5구간 × 수수료 4단계
node coin/backtest/montecarlo.js   # 무작위 매매 300회 대조군
node coin/backtest/feesweep.js     # 파라미터 고정하고 수수료만 변경
```

## 파일
| 파일 | 하는 일 |
|---|---|
| `data/ethusdt-1h.csv` | ETH/USDT 1시간봉 22,760개 (2017-10-26~2020-05-31). 출처: 공개 저장소 `wugool/huobi-historical-data` 1분봉을 집계. 결측 0 |
| `prep.js` | 1분봉 CSV → 1시간봉 집계 (원본은 용량이 커서 저장소에 두지 않는다) |
| `engine.js` | 엔진. 신호는 봉 i 종가까지만 보고, 체결은 봉 i+1 시가 — 미래를 보지 않는다 |
| `selftest.js` | 손으로 계산한 답과 대조하는 자가시험 19건 |
| `strategies.js` | 이동평균교차 · 돈치안돌파 · RSI역추세 · 추세필터+돌파 · 그냥보유 |
| `run.js` | 워크포워드(앞 8개월 최적화 → 다음 4개월 채점, 5회) |
| `montecarlo.js` | 같은 횟수로 아무렇게나 매매한 300회와 비교 |
| `feesweep.js` | 파라미터 고정, 수수료만 0~0.60% |
| `report.html` | 결과 한 장 (차장님용) |

## 엔진이 지키는 것
- **미래 안 봄**: 신호는 봉 i 종가까지, 체결은 봉 i+1 시가.
- **한 번에 포지션 1개**, 추가 진입 없음 (실제 브리지의 `ALLOW_PYRAMID=NO` 와 같게).
- **수수료는 진입·청산 양쪽**, 슬리피지는 항상 불리한 방향.
- **갭이면 손절가가 아니라 시가에 체결** (보수적).
- **숏은 원금 이상 손실 가능** — 자산이 0 이하가 되면 `bust` 로 표시.

## 믿으면 안 되는 것
1. 데이터가 **2020년 5월에 끝난다**. 거래소 시세 API가 이 작업 환경에서 조직 정책(403)으로 막혀 최근 데이터를 못 받았다.
2. 이 시기는 **큰 하락장**이었다(그냥 보유 −52%). 추세추종 숏에 유리한 구간이라 성적이 부풀려졌을 수 있다.
3. 절대 수익률(+4,890% 같은 값)은 2.6년 복리다. **믿을 것은 칸 사이의 비율**이다.
4. 워크포워드에서 수수료를 올렸더니 성적이 좋아진 구간이 있었다 = **파라미터 선택이 불안정**하다. 특정 숫자(20/100 등)를 정답으로 삼지 말 것.
5. Huobi 데이터이고 우리는 딥코인이다.

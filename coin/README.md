# 코인 자동매매 중계 v2 — 설계 한 장 (2026-09-05)

> 결론: 2026-08-08에 만든 v1(deepcoin-bridge.gs)은 **주문이 거절돼도 성공으로 기록하는 결함**이 있어 실전에 쓰면 안 된다. v2는 같은 구조(트레이딩뷰 알럿 → Apps Script → 딥코인)를 유지하되, 주문 전후를 거래소 실제 포지션으로 검증하고, 실수를 막는 문 9개를 코드로 세웠다. 모의 실행기 60건 통과.

## 2. 흐름 — 알럿 하나가 지나가는 문 9개

```
트레이딩뷰 알럿(JSON) ──POST──▶ Apps Script 웹앱
  ① 토큰 확인          틀리면 REJECT. 거래소 호출 0건
  ② 잠금               같은 순간 두 알럿 → 한 건씩. 20초 넘으면 BUSY
  ③ 중복 차단          같은 id(또는 action+symbol+time) 두 번째는 DUP
  ④ 비상정지 KILL      시트 「2.설정」 KILL=YES 면 다음 알럿부터 전부 거절 (폰에서 조작. 캐시 없이 매번 읽음)
  ⑤ 상한 3종           허용 종목 / 1회 계약수 / 하루 실주문 횟수 — 넘으면 줄이지 않고 거절 + 메일. 설정칸이 숫자가 아니어도 거절(열리지 않음)
  ⑥ 거래소 포지션 조회  진입: 같은 방향 있으면 ALREADY_IN / 청산: 거래소 수량으로
  ⑦ 주문               LIVE=NO 면 보낼 내용만 기록(DRY-RUN). YES 면 실제 전송
  ⑧ 주문 후 재조회      기대 수량과 실제 수량 대조 → OK / ⚠ / PARTIAL. 재조회가 실패해도 "주문은 나갔음"을 LIVE 로 남김
  ⑨ 기록·알림          시트 「1.거래로그」 12열 + 오류·실주문은 메일
```

## 4. v1에서 찾은 결함 3건 (근거 포함)

| # | v1 | 무엇이 생기나 | v2 | 근거 |
|---|---|---|---|---|
| 1 | 응답 `code`만 검사 | 딥코인은 거절도 `code:"0"` + `data.sCode:"36"`(잔고 부족) 식으로 온다 → **거절된 주문을 성공으로 기록**하고, 다음 청산 알럿이 없는 포지션을 팔려 함 | `sCode`·`retCode`까지 검사, 거절이면 ERROR + 메일 | ccxt deepcoin 구현의 오류표 (sCode 24/31/36/44/49/194/195) |
| 2 | 청산 수량을 스크립트 속성(로컬 기록)에서 읽음 | 거래소에서 손절이 먼저 나가거나 손으로 정리하면 **기록과 실제가 어긋남** | 청산 직전 `/deepcoin/account/positions` 조회, 실제 수량으로 | 모의 실행 7k: 로컬 10 vs 거래소 13 → 13으로 청산 |
| 3 | 잔고 조회 경로 `/account/balance`, `slOrdPx:'-1'` 전송 | 테스트 함수가 항상 실패 / 규격 밖 항목 전송 | `/account/balances?instType=SWAP`, `slOrdPx` 제거 | ccxt deepcoin 엔드포인트 목록 |

그 밖에 v1에 없던 것: 잠금·중복 차단·KILL·상한·주문 후 검증·자가진단·메일·일일 점검 트리거. 전부 A등급(추가).

## 5. 대안 3개 — 무엇을 잃는가

| | 안 | 얻는 것 | **잃는 것** |
|---|---|---|---|
| **A (권장)** | **Apps Script v2 유지** (이 폴더) | 무료, 서버 없음, 시트로 폰에서 조작·조회, v1 자산 그대로 | 반응 1~3초(구글 콜드스타트) → 시장가라 슬리피지 조금. 초당 1회 제한. 구글 일일 호출 한도(UrlFetch 2만) 안에서만 |
| B | 파이썬 + ccxt 를 내 서버(VPS)에서 | ccxt 가 딥코인 규격을 대신 맞춰줌, 반응 빠름, 되돌리기·백테스트 확장 쉬움 | 월 서버비, 서버 죽으면 아무도 모름(감시를 또 만들어야), 폰에서 KILL 못 누름(별도 UI 필요), 코드가 Claude 손을 떠나 PC 작업 필요 |
| C | 트레이딩뷰 웹훅 중계 유료 서비스에 맡김 | 코드 0, 거래소 연동을 업체가 유지 | 월 구독료, 내 키를 남에게 맡김, 딥코인 지원 여부 미확인(확인 안 했음), 상한·KILL 같은 내 규칙을 못 넣음 |

A를 권하는 이유: 8/19 통화에서 "자동은 되는데 방법은 모른다"가 결론이었고, 지금 필요한 건 **실수 없이 돌아가는 최소 구조**다. B·C는 A가 한 달 무사히 돌고 나서 판단해도 늦지 않다.

## 5-2. 트레이딩뷰 쪽 배선 — 손절이 알럿에 실리게 (v2.3)

「손절 값이 알럿에 실리는가」는 알럿 메시지 칸에 자리표시자를 늘어놓는 방식(B)으로는 **안 된다** — 트레이딩뷰 자리표시자에 손절가는 없다. 그래서 표준은 **Pine 안에서 JSON 을 조립해 `alert_message` 로 넘기는 방식(A)** 이다.

| | A (권장) Pine 조립 | B 수동 JSON |
|---|---|---|
| 손절·익절 | Pine 이 %로 계산해 가격으로 실음 | 빈칸 → 거래소 손절 없음 |
| 수량 | Pine 입력칸 `qtyEth` (ETH) 그대로 | `{{strategy.order.contracts}}` — ETH 인지 확인 필요 |
| 진입가 | 실림 → 브리지가 손절 방향 검사 | `{{close}}` 로 가능 |
| 잃는 것 | Pine 을 열어 두 줄(★)을 바꿔야 함 | 손절 없음, 수량 단위 불확실 |

`pine-alert-wiring.pine` 이 하는 일: 롱 신호 → (숏 있으면 EXIT_SHORT 먼저) → ENTER_LONG(sl=진입가×(1−손절%), tp) / 트레이딩뷰 쪽 `strategy.exit` 도 같이 걸어 이중 안전장치. 거래소 손절이 먼저 나가면 뒤따르는 EXIT 알럿은 브리지가 「포지션 없음 → SKIP」 으로 무해하게 끝낸다.
브리지 v2.3 은 `price` 가 오면 롱 sl<price, 숏 sl>price 가 아닐 때 거절한다 — Pine 계산이 거꾸로여도 주문이 나가지 않는다.

**차장님 전략 코드를 받으면 하는 일:** 원틀의 ★ 두 줄(longSig/shortSig)에 그 전략의 신호를 넣고, 전략이 자체 손절을 갖고 있으면 `slPct` 대신 그 값을 `f_msg` 에 넘기도록 잇는다. 전략이 `strategy.entry` 를 직접 호출하면 그 호출에 `alert_message = f_msg(...)` 만 붙이면 된다.

## 6. 못 하는 것 · 모르는 것 (정직하게)

1. **딥코인 공식 문서 사이트를 이 작업 환경에서 열 수 없었다.** 규격은 ccxt 공개 구현(github ccxt/ccxt `deepcoin.ts`)과 검색 결과 요약으로 대조했다. 신뢰도는 높지만 95%는 아니다 → **SELFCHECK의 「잔고 조회」가 OK 로 나오면 키·서명·경로가 맞는 것**이다. 그게 실증이다.
2. 트레이딩뷰 → Apps Script 웹훅은 구글이 302 리다이렉트를 하는데, 트레이딩뷰는 이를 따라간다는 사용 사례가 많다. **이 세션에서 직접 쏴보지는 못했다** → CHECKLIST 2단계에서 확인.
3. 손절(`slTriggerPx`)이 주문에 붙어 거래소에 남는지, 아니면 별도 트리거 주문으로 넣어야 하는지 **문서로 확정 못 했다** → 모의 기간에 딥코인 앱에서 손절이 걸려 있는지 눈으로 확인.
4. 모의 실행기는 거래소를 흉내 낸 것이다. 실제 딥코인의 응답 형태가 ccxt 예시와 다르면 `checkResp_`가 ERROR로 막는다(주문이 나가는 쪽으로는 틀리지 않게 설계). 
5. **중복 차단은 「먼저 표시」 방식**이라, 알럿 JSON 의 `id` 자리표시자가 깨져 값이 고정되면 그 뒤 정상 알럿까지 전부 DUP 으로 막힌다(주문이 잘못 나가는 쪽이 아니라 안 나가는 쪽으로 틀린다). 로그에 DUP 이 연달아 찍히면 알럿 JSON 을 고치고 실행 메뉴 `초기화_중복기록` 을 돌린다. 오류(ERROR)가 난 알럿도 같은 id 로는 재시도되지 않는다 — 의도한 설계다(이중 주문보다 누락이 낫다).
6. 메일 발송 실패(구글 일일 한도 등)는 조용히 넘어간다. 메일이 유일한 알림 통로이므로, 메일이 며칠 안 오면 「0.자가진단」 탭을 직접 연다.
7. 수익이 나는지는 이 코드가 보장하지 않는다. 이 코드는 **"알럿대로, 한 번만, 상한 안에서, 기록을 남기며"** 만 보장한다.

# 하루 한 장 제안서 은행 — 운영 정본 v1 (2026-09-13)

## 0. 제1규칙 — 이 스킬은 엔진이 아니다

**문서를 만드는 것은 km-proposal v10이다.** 표지·색·글꼴·슬라이드 타입 10종·장수 규칙은 전부 거기가 정본이고, 이 스킬은 **「오늘 무엇을 만들지 고르고, 끊기지 않게 돌리고, 은행을 갱신하는 것」**만 한다.
제안서 디자인을 여기서 새로 정하지 않는다. `assets/build_proposal.js`를 쓰지 않고 좌표를 새로 잡는 것은 금지다(현장마다 디자인이 갈라진다).

자료조사가 필요하면 km-research-writer, 객실 배치 규칙은 km-room-layout, 기구물 단가·사양은 km-fixture-cost가 정본이다.

## 3. 오늘 1건을 뽑는 순서 (고정)

**시트를 못 읽어도 돌아가야 한다.** 자동 실행 세션에는 구글드라이브가 안 붙을 수 있으므로, 오늘 차례는 **상태 추적이 아니라 계산**으로 정한다.

1. **오늘이 평일인가?** 아니면 아무것도 하지 않는다(알림도 안 보낸다).
2. **스위치가 ON인가?** OFF면 아무것도 하지 않는다.
3. **요일 → 유형**
   | 요일 | 유형 |
   |---|---|
   | 월 | I 운영 시나리오 · A 공사한계 |
   | 화 | 객실 기구물 배치 |
   | 수 | J 매뉴얼 · K 넘버링 |
   | 목 | G 기구물 디자인 · D 사양카드 · F 연동 설명자료 |
   | 금 | 레퍼런스 · B/B-2 비교 · E 공동제안 |
4. **주차 → 순번.** **순번 = (ISO 주차 번호 % 그 요일의 건수)**. 요일마다 건수가 달라도 된다(2026-09-13 현재 월5·화4·수4·목6·금4 = 23건).
   같은 주차를 두 번 계산해도 같은 결과가 나오므로 「어디까지 나갔나」를 기록하지 않아도 어긋나지 않는다. 은행에 한 건을 더하면 그 요일의 바퀴만 길어진다.
5. **성격.** 오늘 날짜의 「일」이 홀수면 범용, 짝수면 현장 맞춤.
   - 현장 맞춤인데 그 현장 자료(도면·수량표·회의록)가 없으면 **범용으로 만들고 보고 ④에 적는다.** 없는 수량을 지어내지 않는다.
6. **만든다.** km-proposal v10 → 은행의 장수를 **정확히** 맞춘다(초과·미달 금지).
7. **은행을 갱신한다 — 드라이브가 붙어 있을 때만.** 상태 `완성`, 나간날 기록. 도구가 없으면 건너뛰고 ④에 "시트 미갱신"이라 적는다. **그것 때문에 제작을 중단하지 않는다.**
8. **보낸다.** 대화창 + (컴퓨터 연결 시) 지정 폴더.

## 5. 산출 규격

- **pptx 원본** + **미리보기 PNG 전장** (§6.10 렌더 육안 검수 — 안 보면 완성이 아니다)
- 파일명: `[유형]_[제안서명 20자]_[YYMMDD]_r1.pptx`
- 보고는 **4줄 고정**(①바꾼 것 ②안 건드린 것 ③확인해 주실 것 ④확신 없이 넣은 것)
- ④에는 최소한 이 둘을 판단해 적는다: 지어낸 수치가 있는가 / 현장 자료 없이 범용으로 대체했는가

## 8-1. 실행 환경 준비 (2026-09-13 실측)

자동 실행 세션은 매번 빈 컨테이너로 뜬다. 제작 전에 이것들을 깐다 — 없으면 조용히 실패한다.

```bash
apt-get install -y fonts-noto-cjk          # 없으면 구성도 한글이 전부 네모로 나온다
pip install matplotlib python-pptx
npm install pptxgenjs                       # 빌더가 require 한다
NODE_PATH=$PWD/node_modules node <km-proposal 경로>/assets/build_proposal.js spec.json out.pptx
```
- 빌더는 자기 폴더 기준으로 `require`하므로 **`NODE_PATH`를 설치 경로로 지정**해야 돌아간다.
- **LibreOffice는 이 환경에서 고장나 있다**(2026-09-13 실측 — txt 파일조차 `source file could not be loaded`). 따라서 §6.10 PDF 렌더 육안 검수를 못 한다.
  → 대체 검수: `python-pptx`로 ①장수 ②장별 텍스트 전문 ③표 행·열 수 ④그림 삽입 여부를 대조하고, 보고 ④에 **"렌더 검수 불가 — 구조 검수로 대체"**라고 적는다. **렌더가 안 된다고 제작을 중단하지 않는다.**

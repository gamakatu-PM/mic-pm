# CB모듈_단가장 파이프라인 (코드 방식)

코워크에서 손으로 하던 단가장 시트 조립을 **코드로 고정**한 것 (2026-08-11).

## 역할 분담

- **도면 판독** (무엇이 몇 개인지) → 사람/Claude가 한다. 결과는 `sites/현장명.json`
- **엑셀 조립·수식·검산·버전·이력** → 전부 코드가 한다. 손으로 만들 때처럼 셀이 어긋나거나
  수식이 빠지는 일이 구조적으로 불가능해진다

## 스크립트 3개

| 스크립트 | 역할 |
|---|---|
| `scripts/extract_site.py` | 기존 단가장의 현장 시트 → JSON 역추출 (판독 결과 데이터화) |
| `scripts/add_site.py` | 단가장 + 현장 JSON → 버전 +1 파일 생성. 현장 CB 시트·기구물 시트를 표준 레이아웃(v40 광희동1가 구조)으로 생성/교체, 총괄 미등록 모듈 주황 자동 등록, 「5.변경 이력」 자동 기입 |
| `scripts/validate.py` | 전수 검산 → `total_errors: 0` 확인. ①총괄 명칭 매칭 ②단가 셀 값굳음 탐지 ③요율(×1.5/×1.8/160%=계약가×1.6) ④LibreOffice 재계산 후 수식 오류값 0건 ⑤검산표 불일치 0건 ⑥◆객실 수 합계 = 명시 객실 수 |

## 사용 순서

```bash
# 1. (신규 현장) 판독 결과를 sites/현장명.json 으로 작성
#    (기존 시트를 데이터화할 때) 역추출:
python3 scripts/extract_site.py CB모듈_단가장_v40.xlsx "광희동1가" > sites/광희동1가.json

# 2. 시트 생성 — 버전 자동 +1, 원본은 절대 덮어쓰지 않음
python3 scripts/add_site.py CB모듈_단가장_v40.xlsx sites/광희동1가.json

# 3. 검산 — 마지막 줄 total_errors: 0 이어야 전달 가능
python3 scripts/validate.py CB모듈_단가장_v41.xlsx
```

## 검증된 것 (2026-08-11 라운드트립)

v40에서 광희동1가를 역추출 → 코드로 재조립 → LibreOffice 재계산 결과,
**★ 현장 총액 4종이 원본과 원 단위까지 일치** (실행 103,241,493 / 계약 154,862,384 /
견적 185,834,803 / 예산 247,779,930), `total_errors: 0`.

## 지켜지는 규칙 (km-drawing-cost·운영기준의 코드화)

- 단가는 「1.모듈총괄」 한 곳에서만 — 현장 시트는 INDEX/MATCH 참조, 신규 모듈은 주황 행
- 값으로 굳은 단가 셀은 삭제하지 않고 WARN으로만 보고 (임시단가일 수 있음)
- 요율: 계약 실행가 = 실행 ×1.5 / 견적가 = 실행 ×1.8 / 설계예산가 = **계약가** ×1.6 (구 요율 ×1.3/×1.4 금지)
- 버전은 덮어쓰지 않고 +1, 변경은 「5.변경 이력」에 A/B/C 등급으로 기록
- 미확정 수량·단가는 빈칸 유지 (0으로 채우지 않음 — 미확정과 0을 구분)
- 기구물에는 조립비 30%를 붙이지 않음 (CB만 자재 ×30%)

## 필요 환경

`pip install openpyxl` + LibreOffice(`libreoffice-calc` 포함, 재계산 검증용).
단가장 원본(.xlsx)은 저장소에 넣지 않는다 — 드라이브 「KM_블록작업」이 정본 위치.

## 3. 제 메모 — 56번이 내야 하는 모양 (새 창이 다르게 만들지 않게)
- 수금대장.csv = **기존 7칸 그대로** + 납품예정일 + 근거. 9번·26번·아침 한 장 1·5층은 앞 7칸만 읽으니 그대로 돈다. 새 대장 만들지 않는다.
- **빈칸만 채운다.** 차장님이 적은 값은 새 확정이 와도 안 바꾼다(시험 6절). 지우면(빈칸) 다음 실행에 다시 채운다 — 「빈칸만」 규칙의 자연스러운 결과.
- 입력 통로는 전부 **이미 있는 것** : 회의록 일정/할 일 「납품 | 260929 | 외함」 · 43번 확정 「확정,현장,납품 외함,260929」「계산서 속판」「입금 기구물」「계약금액」「결제조건」 · 28번 견적서.
- 금액 = 계약금액 × 비율. 둘 중 하나가 없으면 **빈칸 + 못 채운 이유**(수금자동_{오늘}.json). 비율은 견적서에서 「자동」, 차장님이 고치면 「손」(다시 계산 안 함).
- 경리 메일·독촉 문안은 **파일만**(보내지 않음). 「N일 지남」 없음. 담당자 이름은 [담당자] 빈칸.
- 현장명 절대 규칙 : meta.site 그대로, 복합회의 등은 대장에 안 넣고 「현장 확인」 이유만.

## 4. 독립 감사 결과 (9/28 새벽, 감사 창 1회) → t56 v2 · 시험 30 → 46
감사가 찾은 것 9건, 전부 v2 에 반영하고 시험 6-1·6-2·6-3 절로 막았다.
1. **오귀속** : 「조선호텔」 확정이 「조선호텔 리뉴얼」 줄에도 붙었다(앞머리 일치) → 정확히 같을 때만, 유일한 앞머리 일치만 허용, 후보 둘이면 아무 줄에도 안 붙이고 이유
2. **줄 지움** : 재저장 때 현장 빈칸·「예)」 줄을 빼고 썼다(C급 삭제) → 줄은 그대로 두고 채우기만

4. **엉터리 숫자** : 계약금액 「9천만원」·결제조건 「30일/60일」 을 int 로 억지로 읽거나 죽었다 → 숫자만, 아니면 이유

7. 결과 폴더·이력 날짜가 실제 오늘이었다 → `--today` 날짜로
8. 견적서 파일 이름에 `_` 가 있으면 현장 일부로만 찾았다 → `_견적서_v` 앞 전부
